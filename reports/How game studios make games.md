# Rebuild GameGold around the playable build

Studios of every size make games the same way underneath the labels. They prove the idea is fun with a cheap playable, prove they can build it at quality with a polished slice, and only then scale up content. Every serious gate is "show me a build plus player evidence," never "show me a finished document." The monolithic game design document (GDD) is largely dead in practice. It has been replaced by short pillars, one-page feature specs and dated design logs that sit beside a build, and the build is the source of truth. Playtesting is weekly and continuous, not a late stage. Scope is controlled early, by pillars and by a willingness to kill projects, and late cuts are the expensive failure mode. Indies follow the same logic with cheaper evidence: jam prototypes, friends who keep playing unprompted, Discord, Steam wishlists and Next Fest demos. GameGold's current linear pipeline runs Concept → AI-written GDD → Systems → Assets → Unity → Playtesting → Deployment. That is close to the 1990s document-first model the industry abandoned. It also puts AI where working developers are most hostile (design authorship, player-facing assets) and puts playtesting at the end, where it can no longer change the game. The fix is to reorder the product around a prototype → slice → production loop with evidence-based gates. AI should interview the designer, scaffold code through a Unity bridge and generate labeled placeholders, and the GDD should be written *out* of decisions rather than *into* the project. On the Unity side, the official bridge is paywalled, in beta, and already deprecating its MCP server in favor of a CLI. GameGold should treat engine transport as swappable, support the official path and the free community server, and keep its own bridge only as a thin fallback.

## Every pipeline converges on two playable gates: "is it fun" and "can we build it"

The canonical sequence is **concept/incubation → prototype → pre-production ending in a vertical slice → production (first playable → alpha → beta/content lock) → release candidate → platform certification → gold → launch → live ops**. The labels are shared, but exit criteria vary enough that milestone payments trigger contract disputes, so practitioners recommend writing explicit exit-criteria documents ([GameDevProducer](https://gamedevproducer.com/posts/what-is-a-game-milestone-alpha-beta-gold/)). The most stable definitions across studios are **alpha = feature complete** (no new gameplay features after this point), **beta = content complete** (playable start to finish), and **gold = certification passed** ([Filament Games](https://www.filamentgames.com/blog/alpha-beta-gold-commitment-high-quality-game-development)). Some sources blur beta into a release candidate ([Game Development Wiki](https://gamedev.fandom.com/wiki/Game_development)). A sample publisher schedule lists 12 milestones from Prototype through Final Build Archive over about 2.5 years ([Deviant Legal](https://deviantlegal.com/guide/game-developers-guide-publishing-agreements/milestone-schedules-advance-payments/)).

| Phase | Key artifacts | Exit gate (evidence) |
|---|---|---|
| Concept / incubation | Opportunity, thesis (incl. what the game will *not* do), audience, pillars, 1–2 page concept | Leadership or team agrees the thesis is worth prototyping |
| Prototype | Throwaway or greybox build of one mechanic, placeholder art | Playtest proof the audience likes it (Riot); team decides to continue or kill (Supercell) |
| Pre-production | First playable, then vertical slice at near-final quality; feature one-pagers; balance spreadsheets; pipeline tools | Slice proves the fun *and* that the team can build it at quality; funding released |
| Production | Content at scale, task boards, weekly playtests, telemetry | Alpha (feature complete) → beta (content complete) |
| Hardening / release | Bug-fix-only "hardening sprints", RC builds, certification submissions | Cert passed = gold; day-one patch |

Riot codifies this unusually clearly. Incubation must establish the Opportunity, a Thesis that includes what the game will *not* do, and the leadership team, all before any code is written ([Riot](https://www.riotgames.com/en/news/r-d-foundations-opportunity-thesis-and-audience)). Prototype exit then requires a defined audience, a playable that shows the key innovations, and **"proof that the audience likes the experience via playtesting"** ([Riot: Prototype](https://www.riotgames.com/en/r-and-d-office/prototype-building-a-games-substance)). Mark Cerny's "Method" says the same in harsher terms. Pre-production ends with a "publishable first playable", a fully polished portion of the game; "once you had the level, then you make 30 of them," and projects whose first playable fails should be cancelled ([Game Developer](https://www.gamedeveloper.com/marketing/conversations-from-gdc-europe-mark-cerny-jonty-barnes-jason-kingsley)). The vertical slice is what gets shown to publishers to fund production ([Xsolla](https://xsolla.com/blog/funding-101-the-impact-of-the-vertical-slice)). Publishers pay in tranches against milestones such as core loop, vertical slice, alpha, beta and release candidate, and the advance "is rarely paid upfront" ([Deviant Legal](https://deviantlegal.com/guide/game-developers-guide-publishing-agreements/milestone-schedules-advance-payments/)).

Who holds the gate varies more than what the gate asks for. AAA and work-for-hire studios answer to publishers or executives with contracts. Supercell "greenlights teams, not ideas": it has no management greenlight process, and the 10–17 person cell kills its own game ([Game Developer](https://www.gamedeveloper.com/business/less-management-more-success-inside-supercell-s-upside-down-organization)). Of Supercell's last 10 games at the time of one talk, **7 died at prototype, 2 at soft launch, and 1 (Clash Royale) shipped** ([Game Developer](https://www.gamedeveloper.com/design/maybe-it-s-time-to-kill-your-game-and-move-on-supercell-on-cutting-its-losses)). Blizzard historically cancelled about half its projects, on the view that "it's way more important that the game is great" than that it hits a date ([GamesRadar](https://www.gamesradar.com/blizzard-canceled-games/)). The studios with the strongest quality reputations share one trait: they are willing to kill or delay on the evidence of a playable, and they own that decision internally.

## Pre-production finds the game, and stalling there causes crunch as surely as skipping it

Pre-production is cheap because the team is small and the work is disposable. One vendor estimate puts AAA pre-production at 12–24 months and 10–15% of budget, with production running 18–36 months at peak headcount. Treat those figures as indicative only ([Innovecs](https://www.innovecsgames.com/blog/aaa-game-development-cost/)). Staffing follows a ramp. Riot's prototype teams are small groups of genre specialists with a throwaway-work mindset ([Riot](https://www.riotgames.com/en/r-and-d-office/prototype-building-a-games-substance)). Marvel's Spider-Man 2 peaked at **264 direct developers plus 116 support staff** and cost **$315M** against a $270M budget ([Kotaku](https://kotaku.com/what-hacked-files-tell-us-about-the-studio-behind-spide-1851115233)). QA peaks between alpha and beta. After gold the team shrinks to a live-ops crew. No named studio publishes a per-phase headcount table, so this curve is synthesized from examples rather than documented anywhere.

Role structures differ just as sharply. Naughty Dog ran a 300-plus-person studio with no one titled "producer," compared with an industry norm of roughly one producer per ten developers ([Game Developer](https://gamedeveloper.com/pc/dice-2010-naughty-dog-s-lemarchand-on-why-the-studio-has-no-producers)). Valve's Half-Life Cabal had no dedicated designers. Its engineers, level designer, writer and animator all built shipping content ([Game Developer](https://www.gamedeveloper.com/design/the-cabal-valve-s-design-process-for-creating-i-half-life-i-)). The lesson for tooling is that "designer" is often a hat worn by builders rather than a separate person writing documents for others.

The best-documented disasters are failures to *converge* in pre-production, not failures to have one. Anthem spent about four years in some form of pre-production, had no playable mission until its final year, and leaned on "BioWare magic," the belief that crunch would pull it together ([Kotaku](https://kotaku.com/how-biowares-anthem-went-wrong-1833731964)). BioWare disputed parts of that account ([PC Gamer](https://www.pcgamer.com/bioware-denies-crunch-was-a-major-topic-among-employees/)). Mass Effect: Andromeda chased procedural planets and lost key leads, and most of the game was reportedly built in its last 18 months ([Kotaku](https://kotaku.com/the-story-behind-mass-effect-andromedas-troubled-five-1795886428)). The positive cases do the opposite. Valve scrapped a Half-Life that "wasn't any fun" and slipped a year to redesign it ([Game Developer](https://www.gamedeveloper.com/design/the-cabal-valve-s-design-process-for-creating-i-half-life-i-)). Nintendo tested Breath of the Wild's physics "chemistry" in a 2D, NES-style prototype that actually ran the real 3D systems viewed from above ([Gamereactor](https://www.gamereactor.eu/nintendo-showed-zelda-breath-of-the-wild-2d-prototype-at-gdc/)). The shared principle is **cheap presentation, real rules**.

Most studios run a hybrid process. Scrum-style sprints handle iteration, and a milestone plan satisfies publishers and platform holders. Clinton Keith warns specifically against starting production before mechanics are proven, and recommends refinement-only "hardening sprints" before release ([Game Developer](https://www.gamedeveloper.com/production/agile-game-development-with-scrum-teams)). Crunch remains endemic. In the IGDA's 2023 survey, **28% reported crunch** and another 25% reported extended long hours they did not call crunch ([IGDA](https://igda.org/news-archive/press-release-the-igda-and-western-university-release-2023-developer-satisfaction-survey/)). Postmortem studies point to management and scope problems, not technology, as the dominant source of failure ([ACM](https://dl.acm.org/doi/abs/10.1145/1486508.1486521); [Microsoft Research](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/06/washburn-icse-2016-2.pdf)). One survey-of-surveys reports **75% of projects with unrealistic scope and 70% cutting features** ([Academia.edu](https://www.academia.edu/8306789/What_went_wrong_A_survey_of_problems_in_game_development)). Those percentages come from secondary summaries and should be checked against the papers before anyone quotes them.

## Design documents shrank to pillars, one-pagers and logs, and the build became the source of truth

Tim Ryan's 1999 model was a 1–2 page concept, then a proposal, then a full design doc that serves as "a bible from which the producer preaches the goal" ([Game Developer](https://www.gamedeveloper.com/design/the-anatomy-of-a-design-document-part-1-documentation-guidelines-for-the-game-concept-and-proposal)). That model survives mostly in classrooms, templates and publisher contracts. Stone Librande's GDC 2010 argument that "no one" reads long design bibles, and that wikis break the relationships between elements, led to annotated one-page diagrams ([Game Developer](https://www.gamedeveloper.com/design/video-one-page-designs)). He later produced more than 100 one-pagers for SimCity (2013) ([GDC Vault](https://gdcvault.com/play/1017708/Simulating-a-City-One-Page)). Daniel Cook proposes a "design log" instead: a 2–10 page starter doc with dated daily entries of play notes and next steps added above it. The log supplements a playable built "as soon as possible" ([Lostgarden](https://lostgarden.com/2011/05/03/game-design-logs/)). Valve's Cabal did produce a 200-plus-page document, but it came out of months of cross-discipline iteration and 200-plus playtests, not before them ([Game Developer](https://www.gamedeveloper.com/design/the-cabal-valve-s-design-process-for-creating-i-half-life-i-)).

The artifact that is consistently practiced from indie to AAA is the **pillars page**: about three short, emotional "why" statements whose real job is to reject features. God of War (2018) used Combat, Father/Son and Exploration, and a "really minimalist and really realistic" pitch was rejected as off-DNA ([DualShockers](https://www.dualshockers.com/god-of-war-art-level-design-info/)). Subnautica used Intoxicating Creation, Thrill of the Unknown and Cascading Hysteria. Charlie Cleveland says an idea that supports no pillar "can be discarded," and admits the team mostly executed on one pillar ([Charlie Cleveland](https://www.charliecleveland.com/game-pillars/)). Unpacking distilled a list of adjectives into contemplation, discovery and expression ([Game Developer](https://www.gamedeveloper.com/design/unpacking-the-design-pillars-of-a-chill-puzzle-game)).

The pitch moved the same way, from document to deck plus build. Publisher decks run about **10–15 slides, scannable in 2–3 minutes**, and lead with a hero image, a logline, comparables, a playable demo, traction (wishlists), the team and a specific budget ([Codecks](https://www.codecks.io/blog/game-pitch-deck/); [Viktori](https://viktori.co/game-pitch-deck-guide-and-template/)). Systems design lives in spreadsheets: cost curves, expected-value calculations and formula-derived stats ([Game Developer](https://www.gamedeveloper.com/design/my-approach-to-economy-balancing-using-spreadsheets)). Designers then tune them against telemetry. God of War Ragnarök watched armor usage across 20 playtesters for unhealthy "clumping" ([Level Design Book](https://book.leveldesignbook.com/process/blockout/playtesting)). Indie tools reflect the same philosophy. HacknPlan sells GDD sections linked directly to tasks as a differentiator ([HacknPlan](https://hacknplan.com/best-project-management-tools-for-game-developers)), which suggests most design docs sit disconnected from the work. No survey quantifies what share of studios use wikis, one-pagers or full GDDs, so "the GDD is dead" rests on practitioner testimony rather than census data.

## Playtesting runs weekly from the first prototype and escalates outward in rings

At Valve, "every Friday, we would playtest the section of the game that we're responsible for with someone from outside the team," and Monday planning targeted that Friday ([Level Design Book](https://book.leveldesignbook.com/process/blockout/playtesting)). Half-Life's Cabal ran **200-plus two-hour sessions**. Observers stayed silent, and each session produced about 100 action items ([Game Developer](https://www.gamedeveloper.com/design/the-cabal-valve-s-design-process-for-creating-i-half-life-i-)). Bungie and Microsoft's Halo 3 research drew on about 600 players and 3,000-plus hours, and nearly all of its findings concerned readability and onboarding: grenades on the ground that players couldn't see, a Brute that killed new players in three shots, and objectives nobody understood ([ABC News](https://abcnews.com/Technology/story?id=3506473&page=1)). Microsoft's RITE method fixes problems *between* participants rather than after the study. In an Age of Empires II test, changes made over 10 participants left the next 6 needing none ([Wikipedia: RITE](https://en.wikipedia.org/wiki/RITE_Method)). Riot runs lab "player labs" long before public test servers, with concept art review, ability tests, full matches, surveys and one-on-ones ([League Nexus](https://nexus.leagueoflegends.com/en-us/2018/03/kaisa-evolves-in-player-labs/)). Subnautica shows telemetry at small scale: it sampled framerate and position every 2 seconds, added an in-game F8 feedback panel, and held weekly public playtests ([Unknown Worlds](https://unknownworlds.com/en/news/creating-telemetry-system-subnautica)). Good tests ask comprehension questions ("what did the orange light mean?"), and designers must not explain or defend the game during a session ([Level Design Book](https://book.leveldesignbook.com/process/blockout/playtesting)).

The division of labor is clear. Weekly internal tests answer whether it works and whether it's fun. Lab tests with fresh players answer comprehension and difficulty. Telemetry answers where and how much. Community and Early Access tests answer long-term engagement. The implication for GameGold is that "Playtesting" cannot be a stage that follows "Unity." It has to be a loop that starts at the first prototype and repeats at every gate.

## Indies replace the greenlight committee with player evidence and grow scope only after the fun is proven

In the indie hits sampled, a small playable came first and documentation followed the fun. LocalThunk had Balatro's chips × mult scoring by the end of December 2021, sent builds to friends in June 2022, and expanded scope only after a friend played for dozens of hours. A publisher reached him by Twitter DM about 18 months in ([LocalThunk](https://localthunk.com/blog/balatro-timeline-3aarh)). Vampire Survivors was built in Phaser with about **£1,100 of bought sprites and music**, launched cheaply into Early Access, and was carried by YouTubers to 70k-plus concurrent players ([Wikipedia](https://en.wikipedia.org/wiki/Vampire_Survivors)). Celeste began as a four-day PICO-8 jam game ([Wikipedia](https://en.wikipedia.org/wiki/Celeste_(video_game))). Hollow Knight began at Ludum Dare 2013, and its Kickstarter raised A$57,000-plus to fund more hires ([Wikipedia](https://en.wikipedia.org/wiki/Hollow_Knight)). More than **100 Steam games started as GMTK jam entries**, though jam success guarantees nothing commercially ([GMTK](https://gmtk.substack.com/p/100-steam-games-that-started-life)). Many "overnight" hits had long apprenticeships behind them: Zeekerss released about 19 games before Lethal Company ([Push To Talk](https://www.pushtotalk.gg/p/how-lethal-company-sold-10-million-copies)). No primary source confirms whether these developers wrote formal GDDs. Their absence is inferred from the timelines.

The indie version of a greenlight gate is market evidence. Balatro's wishlists grew from **48 to 208,401 by launch day**, with the big jumps coming from publisher involvement and two Next Fests rather than from launch itself ([LocalThunk](https://localthunk.com/blog/balatro-timeline-3aarh)). Chris Zukowski's data shows pre-festival wishlists as the strongest predictor of Next Fest results (Spearman r = 0.825), and most games convert **15–25% of wishlists into first-week sales** ([howtomarketagame](https://howtomarketagame.com/2025/03/26/benchmarks-how-many-wishlists-can-i-get-from-steam-next-fest/); [benchmarks](https://howtomarketagame.com/benchmarks/)). He also finds that indies describe their games vaguely and start marketing too late ([Game Developer](https://www.gamedeveloper.com/marketing/super-practical-indie-game-marketing-with-chris-zukowski---gdc-podcast-ep-24)). Early Access works as paid extended playtesting. Hades was built for it from day one, and community feedback reshaped its narrative systems ([Supergiant](https://www.supergiantgames.com/blog/hades-now-out-of-early-access/)). But most games earn less at 1.0 than at their EA launch, so the game must already be fun and hooky when it enters EA ([Game World Observer](https://gameworldobserver.com/2025/12/10/according-to-gamediscoverco-most-games-on-steam-earn-less-after-leaving-early-access-than-they-do-at-launch)).

The indie scope pattern is one strong mechanic, a genre with proven Steam demand, one legible hook, bought or simple assets, and content that scales by adding more of the same rather than new systems (runs, waves, cards). Survivorship bias is heavy here. Thousands of games follow the same prototype-first process and still sell under 2,000 copies, per lower-confidence aggregator data ([Steam Page Analyzer](https://www.steampageanalyzer.com/blog/indie-game-sales-statistics)). The process is necessary but not sufficient, and a tool that promises otherwise is overselling.

## AI earns trust in invisible work and loses it in authorship and shipped content

Developer sentiment has turned sharply. GDC's 2026 survey of 2,300-plus professionals found **36% use gen AI at work, but 52% say it harms the industry**, up from 18% in 2024. The most negative groups are visual art (64%) and **game design/narrative (63%)** ([GDC](https://gdconf.com/article/gdc-2026-state-of-the-game-industry-reveals-impact-of-layoffs-generative-ai-and-more/)). Among users, the top uses are research and brainstorming (81%), code assistance (47%) and prototyping (35%). Vendor surveys paint a rosier picture: Unity reports 79% positive from a sample of 300 ([Game Developer](https://www.gamedeveloper.com/production/unity-claims-79-percent-of-developers-are-feeling-positive-about-generative-ai)), and Google Cloud reports roughly 90% using AI ([PC Gamer](https://www.pcgamer.com/software/ai/87-percent-of-game-developers-are-already-using-ai-agents-and-over-a-third-use-ai-for-creative-elements-like-level-design-and-dialogue-according-to-a-new-google-survey/)). Both vendors sell AI and should be discounted accordingly.

Player-facing AI carries real commercial risk. Steam's January 2026 rules require disclosure of shipped ("pre-generated") and runtime ("live-generated") AI content but exempt developer-efficiency tools such as code assistants ([Everyday AI](https://everydayaiblog.com/steam-ai-disclosure-rules-2026-update/)). One correlational study estimates that disclosing games get about **53% fewer reviews** ([Digital Citizen](https://www.digitalcitizen.life/steam-games-that-disclose-ai-use-may-sell-far-less-new-study-finds/)). The Indie Game Awards rescinded Clair Obscur's awards because gen AI *placeholders* had been used during production, even though they were later patched out ([Dexerto](https://www.dexerto.com/gaming/clair-obscur-expedition-33-indie-game-awards-wins-rescinded-over-gen-ai-assets-3296727/)). On design, a 36-person study found that ChatGPT-assisted ideation produced more ideas but **less distinct ideas across users**, and that users felt less responsible for them. Complete-seeming early ideas also induce design fixation ([arXiv 2402.01536](https://arxiv.org/abs/2402.01536)). No study tests an AI-written GDD directly, so the case against GameGold's current generate-first GDD is inferred from this general creativity research and from designers' hostility.

The pattern that works in studios is Ubisoft's Ghostwriter. Writers define the character and situation, AI drafts barks in volume, and writers edit or discard them ([AI Trace](https://www.aitrace.org/company/ubisoft/practice/f854571e-dc9b-4184-9b79-110dcf289329)). The vibe-coding wave shows AI's strongest real contribution. Pieter Levels built a multiplayer flight sim in about 3 hours ([Indie Hackers](https://www.indiehackers.com/post/tech/pieter-levels-just-announced-the-winners-of-the-2025-vibe-code-game-jam-Uz0wHG4pI3KBOiFhP5YR)), and a jam requiring 80% AI-written code drew 1,100-plus entries, mostly from first-time developers ([levels.io](https://levels.io/winners-of-the-2025-vibe-code-game-jam)). These are jam-scale web games. They prove "first playable fast," not full production. Mapped onto the pipeline:

| Phase | AI helps | AI hurts |
|---|---|---|
| Concept / pillars | Interviewing the designer, surfacing comparables and genre demand, offering *divergent* options, flagging clichés | Writing the concept or pillars for the designer (homogenization, fixation, lost ownership) |
| Prototype | Scaffolding C# and wiring scenes via the engine bridge, greybox, labeled placeholder assets, fixing console errors | Polished generated art that anchors the look before the fun is proven |
| Pre-production / slice | Turning one-pagers into task lists, consistency checks against pillars, drafting spreadsheet balance formulas, playtest-note synthesis | Generating final "style" without a trained style model (consistency is the main blocker) |
| Production | Rote content drafts for human curation (barks, item text), code assist, test automation | Unlabeled AI content shipped to players; bulk design by generation |
| Release | AI provenance report mapped to Steam disclosure categories, patch notes, store-page copy drafts | Undisclosed or untracked AI assets (the Clair Obscur failure mode) |

## Unity's official bridge is paywalled and churning, so GameGold should own the context and treat transport as swappable

Unity's agent story has changed twice in about a year. Muse was retired, and Unity 6.2 (August 2025) introduced Unity AI (Assistant, Generators, Inference Engine), paid through Unity Points after the beta ([CG Channel](https://www.cgchannel.com/2025/08/unity-rolls-out-unity-ai-in-unity-6-2/)). In May 2026 Unity announced **Unity MCP inside com.unity.ai.assistant**. It connects Claude Code, Cursor, Windsurf, VS Code Copilot and others to a running Editor to create GameObjects, read hierarchies, write and attach scripts, and fix console errors. It requires **Unity 6+, a project connected to Unity Cloud, and an active Unity AI trial or subscription**, and it is labeled beta ([Unity blog](https://unity.com/blog/unity-ai-mcp-how-to-get-started)). By package version 2.18 the docs state: **"Unity MCP server is deprecated. Use the Unity command-line interface (CLI) instead."** The CLI promises faster iteration, better stability, and both runtime and Editor targeting. The architecture is a relay binary plus an MCP bridge over IPC, with user approval for direct connections and custom tools registered through attributes ([Unity docs 2.18](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.18/manual/integration/unity-mcp-overview.html)). Aggregator blogs report that MCP moved into the CLI in June 2026, followed by an official Claude Code plugin with 29 skills on September 9, 2026 and a Codex plugin on September 16 ([explainx.ai](https://explainx.ai/blog/unity-official-claude-code-plugin-29-skills-2026)). **These plugin claims are unverified against any first-party Unity source.**

The community alternative is **CoplayDev/unity-mcp** ("MCP for Unity"). It is MIT-licensed, has about **14.5k GitHub stars**, and exposes 47 tool entry points covering scenes, assets, C# scripts, testing, profiling and builds. It supports **Unity 2021.3 LTS through 6.x**, requires Python 3.10+, and works with Claude, Cursor, VS Code, Windsurf, Cline and Gemini CLI ([GitHub](https://github.com/CoplayDev/unity-mcp)). It is sponsored by Aura, which sells a premium Unity product, so its roadmap has commercial incentives of its own. No first-party postmortem exists yet of a commercial Unity game built mainly through an agent plus MCP, and every reported workflow is editor-mechanical rather than design judgment.

This has three implications for GameGold's custom bridge. First, the official path excludes a large share of GameGold's likely users: anyone on Unity 2021/2022 LTS, anyone without Unity Cloud, and anyone unwilling to pay for Unity AI. It has also changed its interface within months, so building *only* on it is a dependency risk. Second, the transport layer is commoditizing. GameGold's defensible value is not moving commands into the Editor. It is the *context* sent across: pillars, the current prototype goal, one-page specs, task lists, and the Unity setup guide for each artifact. The product should hand that context to whichever agent and bridge the user already runs. Third, keeping GameGold's own bridge as a fallback is sensible only if it stays thin. The recommended default order is official Unity CLI/MCP when detected, CoplayDev as the free, version-flexible path, and GameGold's bridge last, covering whatever the other two cannot, such as a zero-setup path for GameGold's own guided steps. These notes do not include an audit of GameGold's bridge. If it duplicates CoplayDev's tool surface without a unique capability, the cheaper move is to freeze it as a fallback and stop extending it.

## GameGold should become a loop around the build, not a linear document factory

The current flow inverts real practice in three ways. It front-loads a full AI-written GDD, which is the artifact studios abandoned and the move the homogenization research warns against. It treats Systems and Assets as stages that come before the game is playable, which is the Anthem pattern of building on unproven ideas. And it puts Playtesting after Unity, where findings can no longer reshape the design. The restructure below keeps GameGold's non-negotiables (stage-gated, everything is a project, the developer owns the craft), but changes what each gate means: from "the AI finished generating" to "you have evidence."

| New stage | Replaces | Designer does | AI does | Gate (evidence, checkable) |
|---|---|---|---|---|
| 1. Pitch & pillars | Concept + GDD | Answers interview questions and writes the hook, three pillars, and what the game won't do | Asks questions, offers divergent options marked as options, shows comparables and genre demand, flags overlap with common ideas | Hook in one sentence, three pillars in the designer's words, "won't do" list, one target genre |
| 2. Core-loop prototype | Systems + Unity (early) | Builds and plays the one mechanic in Unity | Generates the Unity task list and scaffold code via bridge, adds greybox and **labeled** placeholders | Prototype playtest logged, with at least a few outside players and whether they kept playing unprompted; explicit continue / pivot / **kill** choice |
| 3. Vertical slice / demo | Systems + Assets | Brings one representative chunk to target quality | Turns one-pagers into tasks, drafts balance spreadsheets, checks features against pillars, synthesizes playtest notes | Slice playtested by fresh players; comprehension issues resolved (RITE-style); Steam page or demo live for indie users |
| 4. Production | Assets + Unity (bulk) | Scales content and runs a weekly playtest | Drafts rote content for curation, assists with code, keeps a cut list against pillars | Alpha = feature complete (feature lock), beta = content complete |
| 5. Ship | Deployment | Runs hardening sprints and launches or enters EA | AI provenance report (Steam categories), store copy drafts, patch notes | Build passes checklist; all placeholders replaced or disclosed |

Across all five stages, three things stop being stages and become persistent surfaces. **Playtesting** becomes a log that starts at stage 2, with a session template built on comprehension questions and a silent-observer rule. The **design doc** becomes a living output, made of the pillars page, per-feature one-pagers and a dated design log that GameGold assembles from the designer's decisions. It is exportable as a GDD for publishers who want one, but never authored up front by the AI. **Scope control** becomes a pillars filter applied to every new feature request, plus a visible cut list. The kill option at stage 2 should be treated as success, as Supercell does ([Supercell](https://supercell.com/en/news/learning-from-failures/)). A user who kills three prototypes in a month and ships the fourth has used the product correctly.

For indie users, who are GameGold's realistic market, the platform should make the indie substitutes for greenlight explicit. That means jam-sized prototype timeboxes, a "rings" playtest ladder (friends → Discord → Steam Playtest or demo → Early Access), and a reminder to put up a Steam page early, since wishlists compound. It should not pretend to replace publisher gates for AAA teams. It can, however, emit the artifacts those gates expect: a 10–15 slide pitch deck, a vertical-slice checklist and milestone exit criteria.

## Conclusion

The research reframes what GameGold is for. The scarce resource in game development is fast, honest evidence about whether a game is fun and whether it can be built. Documents and assets are not the bottleneck. AI is most welcome where it compresses the time to that evidence (scaffolding, placeholders, test synthesis) and least welcome where it substitutes for the designer's judgment or ships to players. A GDD generator competes in the one area designers resent most. A tool that gets a solo developer from three pillars to a playtested Unity prototype in a weekend, and then helps them decide honestly whether to kill it, does not have that problem.

The engine-bridge churn points the same way. Unity changed its agent interface from Assistant MCP to CLI within months, and a free MIT alternative already covers older versions. Transport is not where GameGold wins. GameGold wins by owning the structured design intent that every bridge and coding agent needs as input, so the Unity integration should be a set of pluggable adapters with GameGold's own bridge kept as a thin fallback. Two open questions remain before committing. The first is whether GameGold's bridge offers anything CoplayDev does not. The second is whether Unity's reported Claude Code plugin is real and free enough to change which adapter should be the default. Both can be checked in an afternoon.
